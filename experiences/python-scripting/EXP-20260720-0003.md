## 1. Objective
Execute external shell commands via Python `subprocess.Popen` while capturing stdout and stderr without locking up or deadlocking the parent process when output volume is large.

## 2. The Trap
Calling `proc.wait()` or manually reading `proc.stdout` line-by-line while stderr pipe buffer is redirected can fill OS pipe buffers (typically 64KB on Linux/Mac). Once the buffer fills, the child process blocks waiting for buffer drain while the parent process blocks in `proc.wait()`, resulting in a permanent deadlock.

## 3. Abstracted Insight
> **Core Principle:** Always use `proc.communicate(timeout=...)` or explicit selector-based non-blocking reads to drain OS stdout/stderr pipes concurrently.

## 4. Validated Path
Use `proc.communicate(timeout=...)` to handle concurrent pipe reading and timeout management automatically.

```python
import subprocess

def run_command_safely(cmd, timeout_sec=30):
    proc = subprocess.Popen(
        cmd,
        stdout=subprocess.PIPE,
        stderr=subprocess.PIPE,
        text=True
    )
    try:
        stdout, stderr = proc.communicate(timeout=timeout_sec)
        return proc.returncode, stdout, stderr
    except subprocess.TimeoutExpired:
        proc.kill()
        stdout, stderr = proc.communicate()
        raise TimeoutError(f"Command '{cmd}' timed out after {timeout_sec}s")
```

## 5. Verification Checklist
- [ ] Verify `proc.communicate()` is used instead of `proc.wait()` or sequential `.readline()`.
- [ ] Confirm process is killed and pipes drained cleanly on `TimeoutExpired`.
- [ ] Check returncode and error output after process completes.
